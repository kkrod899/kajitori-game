# プロダクト・ブリーフ

## 1. プロダクトの一文

家事を何個こなしたかを競うのではなく、家の状態から次に必要なことへ自分で気づき、考え、最後まで閉じる力を育て、見えない仕事の事実を静かに残すゲーム。

## 2. 解決したい問題

家事・育児の分担は、目の前の作業量だけでは測れません。実際には、次の認知負荷が家庭内の誰か一人へ偏りやすくなります。

| 段階 | 具体例 |
|---|---|
| 気づく | オムツ、服、離乳食、提出物などの変化を察知する |
| 判断する | いつ、何を、どれだけ用意するか決める |
| 計画する | 買い物、予定、担当、実施タイミングを組み立てる |
| 実行する | 実際の家事・育児作業を行う |
| 閉じる | 片付け、補充、共有、次回確認まで終える |

本アプリは、この一連のループを家庭運営の単位として扱います。

v0.2では、価値を次の二層で扱います。

| 層 | アプリの役割 | 守ること |
|---|---|---|
| 判断の層 | タスクより先に家の状態事実を渡し、次の一手を利用者が考えられるようにする | 余力が低い日は行動の導出まで支えるが、状態事実と判断理由は必ず残す |
| 尊厳の層 | 見えない仕事の目撃者として、記録から確認できる「この家で起きなかった困りごと」を示す | 誰の手柄かを主語にせず、根拠のない称賛や因果のない推測をしない |

## 3. 中心原則

| ID | 原則 | 意味 |
|---|---|---|
| P-01 | 作業数より認知負荷 | 何件終えたかより、気づき・判断・管理をどれだけ担えたかを重視する |
| P-02 | 指示待ちを置き換えない | パートナーの指示待ちを、アプリの指示待ちへ置き換えない |
| P-03 | 最後まで閉じる | 実行だけでなく、準備・片付け・補充・次回設定を含めて完了とする |
| P-04 | 失敗を責めない | 未完了や先回りできなかった出来事は、減点ではなく次回の学習材料にする |
| P-05 | その日の余力を尊重する | 睡眠不足、体調、仕事、突発対応に応じてクエスト量を変える |
| P-06 | 月齢だけで断定しない | 月齢、発達状況、家庭環境、個別予定を組み合わせて提案する |
| P-07 | パートナーの管理負担を増やさない | 承認、採点、入力などをパートナーへ過度に要求しない |
| P-08 | 安全情報は出典を持つ | 育児・安全・健康に関する提案には公的または専門的な根拠と確認日を持たせる |
| P-09 | 慣れるほど自立する | 初期は詳しく支援し、習熟すると通知や指示を減らす |

## 4. ゲームにする対象

プレイヤーが成長させるのは、家事処理速度だけではありません。

| 能力 | ゲーム内での表現例 |
|---|---|
| 観察力 | 在庫切れ、サイズ変化、期限を早めに察知する |
| 判断力 | 家族へ質問を丸投げせず、必要な情報を集めて判断する |
| 計画力 | 数日から数週間先の準備を組み立てる |
| 完結力 | 作業後の片付け、補充、共有まで閉じる |
| 改善力 | 次に気づけるサインを見つけ、同じ見落としが起きない仕組みを作る |
| 協働力 | 能力、体調、予定に応じて無理のない分担を調整する |

## 5. 避けること

- 夫婦間の競争ランキング
- 家事件数だけによる50対50判定
- 未完了を罪悪感や罰へ結び付ける設計
- パートナーによる毎回の承認を必須にする設計
- 月齢だけに基づく医療・発達判断
- 家族構成、性別、授乳方法などを一つに固定すること
- ゲームのスコアを現実の愛情や貢献度そのものとして扱うこと

## 6. v0.2で検証したい仮説

最初の基本場面は新生児のいる家庭とする。上の子・保育園は任意設定で有効にし、該当しない家庭へそのタスクを出さない。

| 仮説 | 確認方法 |
|---|---|
| 余力に応じた0〜3件なら、睡眠不足の日も圧迫感なく次の一手を選べる | 提示直後の主観負担と、無理なく着手できたかを確認する |
| 「今やる理由」と「終わりの条件」があると、指示ではなく判断基準を学べる | 提案前に自分で気づけた回数と、理由を見ずに判断できた項目を確認する |
| 曜日・月齢・予定による静的な先読みで、必要になる前の自発対応が増える | 期限前に準備を始められた項目と、不要提案の割合を確認する |
| 作業単位より担当領域の完結ループを持つ方が、認知負荷の偏りを減らせる | ヒントなしで最後まで閉じられる担当領域数を確認する |
| タスクより先に家の状態事実を示すと、判断が利用者の頭に残る | 状態を見て自分で行動を選べた項目と、1日1問で把握できていた領域を確認する |
| 記録に裏付けられた「起きなかったこと」が、承認のない日の支えになる | 表示が役立ったかと、根拠のない項目が混ざっていないかを確認する |

継続日数やアプリ滞在時間は主要な成功指標にしない。支援が減り、利用頻度が下がっても、自分で安定して回せる担当領域が増えていれば成功と扱う。v0.2の今日画面では、達成率や数値ゲージを成長の評価として表示しない。ゲームとしての成長感は、家事件数ではなく能力・担当領域を軸に後続で再設計する。

さらに、記録に裏付けられた事実を振り返ることで、利用者本人が育休終了時に「取って損はなかった」と言えるかを確認する。他者からの称賛や採点は成功条件にしない。

## 7. 現段階の非目標

- 医療機器や診断アプリになること
- 育児記録アプリの全機能を再現すること
- SNS、課金、広告、公開ランキング
- 本番バックエンドや家族同期の即時実装
