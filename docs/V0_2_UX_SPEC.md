# v0.2 UX specification

Status: Revised for approved two-layer concept
Date: 2026-07-23
App implementation: Not started

## 1. プロダクト定義

| 項目 | v0.2の定義 |
|---|---|
| 一文 | 家の状態から次の一手に自分で気づき、判断し、閉じる力を育てながら、見えない仕事の目撃者になる先読みトレーナー |
| 最初の利用者 | 育休中に日中も家庭運営を担う父親 |
| 最初の生活場面 | 新生児のいる家庭を基本とし、上の子・保育園は該当者だけが初回設定で有効化 |
| 間接的な受益者 | パートナー、赤ちゃん、上の子 |
| 利用形態 | まずは利用者1人で完結。パートナーのインストール・入力・承認は不要 |
| 成功 | アプリを見る時間が増えることではなく、先回りできる領域が増え、育休終了時に「取って損はなかった」と自分で言える事実が残ること |

## 2. v0.2で検証する核

| ID | 核となる機能 | 検証したいこと |
|---|---|---|
| C-01 | 余力に応じた最大3件 | 大量の家事候補から「今日やること」を選ぶ認知負荷を減らせるか |
| C-02 | 理由カード | 指示ではなく判断基準を学び、自分で気づけるようになるか |
| C-03 | 静的な先読み | 曜日・月齢・予定から、必要になる前に準備できるか |
| C-04 | 状態主役のカード | タスクではなく家の状態を先に受け取ることで、判断が自分の頭に残るか |
| C-05 | 起きなかったことの記録 | 称賛や他者の承認がない日に、記録に裏付けられた事実が自分の支えになるか |

## 3. 今回やらないこと

- パートナーとのアカウント共有、承認、採点
- AIによる自由推論や自動献立
- 消耗品の使用ペース自動学習
- 自動で通知を減らす卒業アルゴリズム
- 公開ランキング、連続記録、夫婦比較
- 本番バックエンド、課金、SNS

## 4. 1日の基本ループ

| 時点 | 利用者の状態 | アプリの役割 | 操作上限 |
|---|---|---|---:|
| 朝 | 睡眠不足や予定変更を含め、今日の余力が不明 | 余力を選び、今日の0〜3件を提示 | 約30秒 |
| 朝または任意 | 家の状態をどこまで把握できているか曖昧 | 1日1回だけ状態を問い、把握または確認の入口をつくる | 任意、1〜2タップ |
| 日中 | 抱っこ、授乳、家事の割り込みが多い | 自分で選んだ「現在の一手」だけを大きく表示 | 1回5秒 |
| 任意 | 提案になかった必要事項へ自分で気づいた | 今日画面から先読み達成を記録 | 1タップ+Undo |
| 夜または手が空いた時 | 明日の不安が残る | 明日以降の芽を最大3件だけ見せる | 任意、約60秒 |

「1日1問」は`今、◯◯の残りはパッと分かりますか？`と問い、回答は`分かる / 見てくる`の二択だけにする。`分かる`はその領域を把握できている事実として記録し、`見てくる`では確認後に状態を`十分 / そろそろ / 切れた`から1タップで残せる。回答は任意で、未回答への減点、催促、連続記録切れはない。

夜の確認も「1日1問」も新たな義務にしない。確認しなくても減点、連続記録切れ、翌日への罰は発生しない。

## 5. 情報設計

主要ナビゲーションは4タブ以内にする。

| タブ | 目的 | 主な内容 |
|---|---|---|
| 今日 | 今やることを自分で選べる | 余力、次の候補、現在の一手、今日選ばれた0〜3件、先読み達成、Undo |
| 先読み | 明日以降を早めに持つ | 明日、今週、この先の芽、曜日・月齢・予定の理由 |
| 担当 | 作業ではなく領域を持つ | 在庫、食事、洗濯、予定などの担当状況と完結ループ |
| 成長 | 見えない仕事の事実と判断の変化を振り返る | この家で起きなかった困りごと、自分で気づけたこと、次に気づくヒント |

「気づき」は独立タブにせず、成長の中へ含める。認知負荷を担うという根幹を見失わないよう、「担当」を主要タブとして残す。

## 6. 初回設定

目標は2分以内。後から変更でき、分からない項目は飛ばせる。

| Step | 入力 | 目的 |
|---:|---|---|
| 1 | 赤ちゃんの誕生日または月齢 | 月齢に応じた候補を絞る |
| 2 | 上の子、保育園、授乳方法など | 不要なカテゴリを初日から隠す。上の子・保育園は任意 |
| 3 | 育休期間と、おおまかな生活時間帯 | 終日型の提案タイミングを作る |
| 4 | 通知方針 | 初期値は重要期限のみ。常時通知しない |

初回設定の最後に、説明を読ませるのではなく「今日の1件」を提示し、最初の成功体験へ直結させる。

担当領域は初回設定で選ばせない。利用3日目または3件完了後の早い方で、最近扱ったカテゴリから「この領域を自分で回してみますか」と任意提案する。提案は閉じられ、後から担当タブでいつでも選べる。

## 7. 今日画面

### 7.1 余力

医学的・精神的評価ではなく、今日の提案量を決める任意入力とする。

| 選択肢 | 意味 | 提案件数 |
|---|---|---:|
| 守る日 | 最低限で家庭を守る | 0〜1件 |
| 回す日 | 通常運転で回す | 最大2件 |
| 先回り日 | 少し先まで準備する | 最大3件 |

未選択時は「回す日」を仮表示するが、変更を要求しない。余力を下げても、未完了やレベル低下として扱わない。

#### 0件時

安全・期限上の必須候補がなく、守る日で0件となった場合も空画面にしない。

- 見出し: `今日は増やさなくて大丈夫`
- 本文: `必要な育児と休息で十分です。先読みは閉じたままでかまいません。`
- 完了率、未完了数、繰越警告は表示しない。
- 明日以降を見たい利用者のため、目立たない`先読みを見る`だけを置く。
- 対象期間を記録で確認できる場合だけ、`この家で起きなかった困りごと`の最新記録へ静かに移動できる導線を置く。該当記録がなければ導線ごと表示しない。

### 7.2 状態主役のカード

カードは次の順で見せる。

1. 家の状態事実を見出しとして最も大きく表示
2. 状態から導いたアクションを控えめに表示
3. 今やる理由を1行
4. 終わりの条件を1行
5. 目安時間
6. 状態に応じた主要操作

カードの主役はタスクではなく、確認済みの状態事実とする。消耗品の状態入力は`十分 / そろそろ / 切れた`の3段階だけとし、個数、残量率、使用量などの数値入力を要求しない。入力がない状態を推測で補わない。

完了後は数秒間Undoを表示する。スワイプ操作は補助として許可するが、主要操作は大きなボタンでも行える。

#### 「現在の一手」の決め方

1. 状態から導いた今日の候補には`今やる`を表示する。
2. 利用者が選んだものだけを「現在の一手」として固定表示する。
3. 未選択時は優先度が最も高い1件を「次の候補」として仮表示するが、自動選択・自動開始はしない。
4. 現在の一手では`完了`、`あとで`、`今日は見送る`を表示する。
5. 完了または見送り後は固定を解除し、次も利用者が選ぶ。

アプリは候補と理由を提示するところまでを担い、実行順の最終判断は利用者に残す。

### 7.3 状態主役のカード例

| 状態事実 | 導出アクション | 今やる理由 | 終わりの条件 |
|---|---|---|---|
| 次サイズ 未確認 | オムツの次サイズを確認 | 生後3か月。サイズアップの兆候を確認する時期 | 現在の体重・跡・漏れを確認し、買うか保留を決めた |
| 布団カバー 明日持ち帰り | 金曜の保育園セットを確認 | 持ち帰った後の置き場を先に決めておける | 洗濯へ回す場所まで決めた |
| 夜間セット そろそろ | 夜間セットを補充 | 寝る前にそろえておくと、夜中に探さずに済む | オムツ、ガーゼ、着替えが所定数そろった |

保育園の例は、初回設定で保育園を有効にした場合だけ表示する。月齢情報は断定ではなく、確認するきっかけとして表現する。

## 8. 今日の0〜3件を選ぶ基準

候補は次の順で絞る。

| 優先 | 基準 | 例 |
|---:|---|---|
| 1 | 安全・期限 | 寝床安全、提出期限、通院準備 |
| 2 | 今日放置すると後工程が詰まる | ミルク、洗濯、夕食判断 |
| 3 | 自分の担当領域 | 在庫担当なら補充確認 |
| 4 | 余力に収まる | 5分で終わる一手へ分割 |
| 5 | 同種タスクの重複回避 | 在庫確認ばかり3件にしない |

表示されなかった候補は失敗や未完了にせず、利用者向けの集計対象にも入れない。

## 9. 先読み画面

予測AIではなく、まずは設定とテンプレートから静的に出す。

| 範囲 | 表示例 | 操作 |
|---|---|---|
| 明日 | 保育園の曜日差分、ゴミの日 | 今日準備へ入れる / そのまま |
| 今週 | 在庫確認、健診準備、提出期限 | 担当する / 後で見る |
| この先 | 次サイズ、離乳準備、安全対策 | 時期が来たら確認 / 今は不要 |
| 上の子設定が有効な家庭のみ | 上の子と2人だけの10分 | 今日準備へ入れる / 後で見る / 今は不要 |

先読み項目は自動的に今日のノルマへ入れない。利用者が「今日準備へ入れる」を選んだ場合だけ、今日の枠へ追加する。

`上の子と2人だけの10分`は、関係改善の達成課題や子どもの感情の攻略として扱わない。拒絶が見られる時期の補助コピーは`よくある波`にとどめ、感情の理由や結果を断定しない。

## 10. 担当画面

タスクを半分ずつ取るのではなく、領域の開始から終了までを持つ。

| 担当領域 | 完結ループ例 |
|---|---|
| オムツ・消耗品 | 残量に気づく→必要量判断→注文→収納→次回確認 |
| 食事 | 方針決定→在庫確認→調達→準備→片付け |
| 保育園 | 連絡確認→差分判断→準備→提出→補充 |
| 洗濯 | 回収→洗う→乾かす→畳む→定位置へ戻す |
| 予定 | 情報収集→カレンダー反映→準備→当日対応→次回設定 |

担当状態は `未選択 / 試している / 担当中 / 自分で回せている` とする。パートナーに担当認定や承認を求めない。v0.2では領域名、現在の状態、完結ループの1行表示までとし、工程別の詳細画面や細かな進捗編集はLaterとする。

## 11. 成長画面

件数、連続日数、夫婦比較ではなく、`起きなかったことの記録`と`自分で気づけた`を中心に事実を見せる。

| 表示 | 内容 | 表示条件 |
|---|---|---|
| この家で起きなかった困りごと | `この2週間: 在庫切れ 0回`など、家庭で回避できた困りごとの事実 | 対象期間の状態確認と行動の記録がそろい、因果のつながる範囲で発生有無を判定できる場合だけ |
| 自分で気づけた | 提案前に必要事項を察知した項目名と、その時に残した状態 | 利用者が自分で記録した場合だけ |
| 次に気づくヒント | 次回に自分が状態変化を見つけるためのサイン | 利用者が任意でサインを残した場合だけ |

`起きなかったことの記録`には次の制約を置く。

1. 見出しは`この家で起きなかった困りごと`とし、誰の手柄かを示す主語を置かない。
2. 記録済みの状態確認と行動から因果を確認できる事実だけを表示する。
3. 記録が欠けて発生有無を確認できない期間は、`0回`と推測せず項目ごと表示しない。
4. `よくやった`、`頑張った`などの称賛コピーを添えず、事実だけを列挙する。
5. 守る日の0件画面から静かに見返せるようにする。

`最後まで閉じた`と`自分で回せている領域`の個別集計、能力バッジ、その他のゲーム成長表現はLaterとする。担当画面には完結ループの現在状態だけを残す。

### 11.1 「自分で気づけた」の入口

今日画面に、44px以上の副次ボタン`提案になかったことに気づいた`を常設する。

1. タップ時点で先読み達成を1件保存し、Undoを表示する。
2. 何に気づいたかのカテゴリ選択は任意とし、入力せず閉じられる。
3. XP、連続記録、順位、達成数の強調には使わない。
4. v0.2では自立度検証のローカル記録として使い、パートナーへ共有しない。

### 11.2 「1日1問」と卒業

1. 1日1回だけ、現在質問対象の領域から1問を表示する。通知で回答を迫らない。
2. `分かる`は状態把握の記録とし、同じ領域で把握できている記録が重なるほど、その領域を質問候補へ出す頻度を下げる。
3. `見てくる`の後は、確認結果を`十分 / そろそろ / 切れた`の3段階で任意記録できる。
4. 質問頻度の調整は回答記録に基づく固定ルールとし、残量の使用ペース推測や自由推論は行わない。
5. 未回答、`見てくる`、`切れた`を失敗・減点として扱わない。

## 12. 状態と言葉

| 現在の表現 | v0.2候補 | 意図 |
|---|---|---|
| 妻ケア | 休息をつくる | 相手をケア対象として扱わず、時間を作る行動へ |
| 妻の脳内カレンダーを奪う | 家族の予定を先に持つ | 敵対表現を自律的な行動へ変える |
| 取り逃がし | 次に気づくヒント | 相手の行動ではなく、自分が次に見つけられるサインを残す |
| 妻に聞かずに進める | 自分で決めて進める | パートナー回避ではなく自律を示す |
| 未回収 | 今日の候補外 | やらなかった失敗に見せない |
| 達成率 | 今日できたこと | 数値やゲージを使わず、完了した項目名だけを振り返る |

状態入力は`十分 / そろそろ / 切れた`の3段階とする。数値入力は求めず、未入力を異常や失敗として扱わない。

上の子の拒絶が見られる時期に添える表現は`よくある波`までとし、子どもの心理、原因、改善結果を断定しない。

次の表現は禁止する。

| 禁止する表現 | 理由 |
|---|---|
| `あなたのおかげで防げた`、`パパが守った`など主語つきの手柄 | 家の記録を個人の功績やパートナーへの主張に変えないため |
| `よくやってるね`、`頑張ったね`など根拠のない称賛 | 見えない仕事を空虚な評価で置き換えず、確認できる事実を残すため |
| `パパ嫌い解消`など感情を攻略対象にする言葉 | 子どもの感情をゲームの達成対象にしないため |

タスク状態は `今日やる / あとで / 今日は見送る / 完了 / もう済んでいた / 今は不要` を扱う。

`もう済んでいた`では、誰が対応したかを保存・表示・集計しない。任意で残せるのは「残量が半分」「玄関に袋が出ている」など、次回に自分が早く気づくためのサインだけとする。パートナーの行動履歴は記録対象にしない。

## 13. 片手・疲労時のUX

- 主要タップ領域は44px相当以上。
- 本文は原則14px相当以上。
- 主要操作を色だけで区別しない。
- 完了は1タップ、直後にUndo可能。
- スワイプだけに依存しない。
- 夜間は無音、低刺激、強い白背景を避ける。
- アニメーションは短く、Reduce Motionへ対応できる構造にする。
- 「今日は見送る」に理由入力を要求しない。

## 14. v0.2の範囲

| Must | Later | Avoid |
|---|---|---|
| 2分以内の初回設定 | 残量ペースの自動学習 | パートナー承認 |
| 余力による0〜3件 | 卒業時の自動間引き | 夫婦比較 |
| 理由・完了条件 | 家族アカウント同期 | 連続日数ペナルティ |
| 曜日・月齢の静的先読み | AIによる自由推論 | 50件常時表示 |
| 初回後の担当領域の任意選択 | 「判断基準を覚えた」の自己申告 | 通知の常用 |
| 大きなタップ操作とUndo | 図鑑拡充 | 完了率100%の強制 |
| 先読み達成の1タップ記録 | 能力・担当領域ベースのゲーム成長表現 | 家事件数ベースのXP・レベル |
| 状態の3段階記録 | 担当領域の工程別詳細と細かな進捗編集 | 数値での残量入力 |
| 任意の「1日1問」 | 自分で回せている領域の個別集計・能力バッジ | 未回答への催促・減点 |
| 起きなかったことの記録 | 行動記録と因果のつながらない困りごとの推測 | 主語つきの手柄・空虚な称賛 |

### 14.1 範囲の相殺

Mustの追加による肥大を避けるため、担当画面は`領域名 / 現在の状態 / 完結ループ1行`までに限定する。成長画面は`起きなかったことの記録 / 自分で気づけた / 次に気づくヒント`だけを扱い、工程別詳細、個別集計、能力バッジ、その他のゲーム成長表現はLaterへ移す。

## 15. 受入条件

| ID | 条件 |
|---|---|
| A-01 | 初回設定を2分以内で終え、今日の1件まで到達できる |

| A-03 | 各状態カードに導出アクション、「今やる理由」、「終わりの条件」がある |
| A-04 | 余力を下げても、未完了数・失敗・連続記録切れとして表示されない |
| A-05 | パートナーによる操作を一度も要求しない |
| A-06 | 先読み候補は利用者が選ぶまで今日のノルマへ入らない |
| A-07 | 担当領域の完結ループを画面上で確認できる |
| A-08 | 完了操作を1タップで行え、Undoできる |
| A-09 | 主要機能を4タブ以内で利用できる |
| A-10 | 達成率、数値ゲージ、取り逃がし、夫婦比較、連続日数ペナルティを表示しない |
| A-11 | カードの最上位情報が、推測ではなく確認済みの状態事実である |
| A-12 | 起きなかったことの記録に、個人を手柄の主語にする表現と空虚な称賛表現がない |
| A-13 | 「1日1問」は未回答でも減点・連続記録切れ・催促がない |
| A-14 | 状態入力に個数、残量率、使用量などの数値入力を要求しない |
| A-15 | 0件時にも休息を肯定する画面が表示され、警告や繰越を出さない |
| A-16 | 「現在の一手」は利用者が選び、アプリは未選択の候補を自動開始しない |
| A-17 | 今日画面から先読み達成を1タップで記録し、Undoできる |
| A-18 | `もう済んでいた`で対応者を保存・表示・集計しない |

## 16. v0.2の検証方法

最初は主要利用者本人による7〜14日間の実生活利用でC-01〜C-05を確認する。第三者への拡張性テストは、核を修正した後に行う。

| 検証対象 | 取得する最小情報 | 画面上の扱い |
|---|---|---|
| C-01 余力0〜3件 | 提示数、今やる選択、完了、あとで、見送り | 完了率や点数として見せない |
| C-02 理由カード | 理由カードを開いたか、先読み達成の1タップ | 自立度の順位や点数にしない |
| C-03 静的先読み | 今日へ入れた、後で見る、今は不要 | 不要提案の改善にだけ使う |
| C-04 状態主役のカード | 1日1問の回答、3段階の状態、状態を見て自分で選んだアクション | 未回答や`切れた`を失敗にしない |
| C-05 起きなかったことの記録 | 表示根拠となった状態確認・行動記録、表示後に役立ったかの本人回答 | 根拠のない項目は生成せず、スコアにしない |
| 担当領域 | 完結ループの到達点 | 領域ごとの次の一手を整えるために使う |

利用終了時に本人へ、負担、理由の納得感、先回りへの変化に加え、記録を見て育休を「取って損はなかった」と自分で言えるかを短く振り返ってもらう。パートナーは日常的な入力・承認・採点を行わない。希望がある場合のみ、一度だけ画面を見た印象を5分以内で聞き、監視・採点に見えないかを確認する。
