# v0.2 UX specification

Status: Slice 01 implemented / post-review Ready
Date: 2026-08-30
App implementation: Slice 01 complete, reviewed 2026-08-30

## 1. プロダクト定義

| 項目 | v0.2の定義 |
|---|---|
| 一文 | 家の状態から次の一手に自分で気づき、判断し、閉じる力を育てながら、見えない仕事の目撃者になる先読みトレーナー |
| 最初の利用者 | 育休中に日中も家庭運営を担う父親 |
| 最初の生活場面 | 新生児のいる家庭を基本とし、上の子・保育園は該当者だけが初回設定で有効化 |
| 間接的な受益者 | パートナー、赤ちゃん、上の子 |
| 利用形態 | まずは利用者1人で完結。パートナーのインストール・入力・承認は不要 |
| 成功 | アプリを見る時間が増えることではなく、先回りできる領域が増え、育休終了時に「取って損はなかった」と自分で言える事実が残ること |

## 2. v0.2で検証する核

| ID | 核となる機能 | 検証したいこと |
|---|---|---|
| C-01 | 余力に応じた最大3件 | 大量の家事候補から「今日やること」を選ぶ認知負荷を減らせるか |
| C-02 | 理由カード | 指示ではなく判断基準を学び、自分で気づけるようになるか |
| C-03 | 静的な先読み | 曜日・月齢・予定から、必要になる前に準備できるか |
| C-04 | 状態主役のカード | タスクではなく家の状態を先に受け取ることで、判断が自分の頭に残るか |

## 3. 今回やらないこと

- パートナーとのアカウント共有、承認、採点
- AIによる自由推論や自動献立
- 消耗品の使用ペース自動学習
- 自動で通知を減らす卒業アルゴリズム
- 通知方針を選ばせる初回設定UI
- 担当領域を選択・認定するUI
- 公開ランキング、連続記録、夫婦比較
- 本番バックエンド、課金、SNS

## 4. 1日の基本ループ

| 時点 | 利用者の状態 | アプリの役割 | 操作上限 |
|---|---|---|---:|
| 朝 | 睡眠不足や予定変更を含め、今日の余力が不明 | 余力を選び、今日の0〜3件を提示 | 約30秒 |
| 朝または任意 | 家の状態をどこまで把握できているか曖昧 | 1日1回だけ状態を問い、把握または確認の入口をつくる | 任意、1〜2タップ |
| 日中 | 抱っこ、授乳、家事の割り込みが多い | 自分で選んだ「現在の一手」だけを大きく表示 | 1回5秒 |
| 任意 | 提案になかった必要事項へ自分で気づいた | 今日画面から先読み達成を記録 | 1タップ+Undo |
| 夜または手が空いた時 | 明日の不安が残る | 明日以降の芽を最大3件だけ見せる | 任意、約60秒 |

「1日1問」は`今、◯◯の残りはパッと分かりますか？`と問い、回答は`分かる / 見てくる`の二択だけにする。`分かる`はその領域を把握できているという回答記録だけを残し、現在状態の鮮度は更新しない。`見てくる`では確認後に状態を`十分 / そろそろ / 切れた`から1タップで任意記録できる。

回答は任意で、未回答への減点、催促、連続記録切れはない。夜の確認も「1日1問」も新たな義務にしない。

## 5. 情報設計

主要ナビゲーションは4タブ以内にする。

| タブ | 目的 | 主な内容 |
|---|---|---|
| 今日 | 今やることを自分で選べる | 余力、次の候補、現在の一手、今日選ばれた0〜3件、今日のあとで、先読み達成、Undo |
| 先読み | 明日以降を早めに持つ | 明日、今週、この先の芽、曜日・月齢・予定の理由 |
| 担当 | 作業ではなく領域単位の完結を見る | 在庫、食事、洗濯、予定などの完結ループを1行で確認する。v0.2では閲覧のみ |
| 成長 | 見えない仕事の事実と判断の変化を振り返る | 証拠のある「この家で起きなかった困りごと」、自分で気づけたこと、次に気づくヒント |

「気づき」は独立タブにせず、成長の中へ含める。担当領域の選択、認定、工程別進捗はLaterとする。

## 6. 初回設定

目標は2分以内。後から変更でき、分からない項目は飛ばせる。

| Step | 入力 | 目的 |
|---:|---|---|
| 1 | 赤ちゃんの誕生日または月齢 | 月齢に応じた候補を絞る |
| 2 | 上の子、保育園、授乳方法など | 不要なカテゴリを初日から隠す。上の子・保育園は任意 |
| 3 | 育休期間と、おおまかな生活時間帯 | 終日型の提案を調整する |

初回設定の最後に、説明を読ませるのではなく「今日の1件」へ直結させる。通知設定と担当領域選択は初回設定に含めない。

## 7. 今日画面

### 7.1 余力

医学的・精神的評価ではなく、今日の提案量を決める任意入力とする。

| 選択肢 | 意味 | 今日のアクティブ上限 |
|---|---|---:|
| 守る日 | 最低限で家庭を守る | 0〜1件 |
| 回す日 | 通常運転で回す | 最大2件 |
| 先回り日 | 少し先まで準備する | 最大3件 |

未選択時は「回す日」を仮表示するが、変更を要求しない。余力を下げて上限を超えた場合、現在の一手を優先して残し、超過分は`今日のあとで`へ移す。これは失敗・未完了・繰越として扱わない。

#### 0件時

安全・期限上の必須候補がなく、守る日で0件となった場合も空画面にしない。

- 見出し: `今日は増やさなくて大丈夫`
- 本文: `必要な育児と休息で十分です。先読みは閉じたままでかまいません。`
- 完了率、未完了数、繰越警告は表示しない。
- 明日以降を見たい利用者のため、目立たない`先読みを見る`だけを置く。
- 証拠イベントが1件以上ある場合だけ、成長画面の最新事実へ静かに移動できる導線を置く。

### 7.2 状態主役のカード

カードは次の順で見せる。

1. 家の状態事実を見出しとして最も大きく表示
2. 状態から導いたアクションを控えめに表示
3. 今やる理由を1行
4. 終わりの条件を1行
5. 目安時間
6. 状態に応じた主要操作

#### 状態事実の鮮度

カード最上位に置ける事実は次の2種類だけとする。

| 種類 | 現在事実として使える条件 | 期限切れ時の表示 |
|---|---|---|
| 利用者が確認した3段階状態 | `十分 / そろそろ / 切れた`を利用者が記録した当日のローカル日付内だけ | 古い値は表示せず、`最終確認: 昨日`、`今日 未確認`など確認日時の事実へ置き換える |
| 保存済み設定・静的ルールから確定する予定事実 | 対象日・曜日・設定条件が現在も一致している間だけ | 条件が外れたら表示しない |

未入力や期限切れの値を推測で補わない。`1日1問`の`分かる`回答は状態値の確認ではないため、鮮度を延長しない。

状態入力は`十分 / そろそろ / 切れた`の3段階だけとし、個数、残量率、使用量などの数値入力を要求しない。

完了後はUndoを表示する。スワイプ操作は補助として許可するが、主要操作は44px相当以上のボタンでも行える。

#### 「現在の一手」の決め方

1. 状態から導いた今日の候補には`今やる`を表示する。
2. 利用者が選んだものだけを「現在の一手」として固定表示する。
3. 未選択時は優先度が最も高い1件を「次の候補」として仮表示するが、自動選択・自動開始はしない。
4. 現在の一手では`完了`、`あとで`、`今日は見送る`を表示する。
5. 完了、あとで、見送り後は固定を解除し、次も利用者が選ぶ。

アプリは候補と理由を提示するところまでを担い、実行順の最終判断は利用者に残す。

#### `あとで`と`今日は見送る`

| 操作 | 当日の挙動 | 翌日の挙動 |
|---|---|---|
| `あとで` | 今日のアクティブ0〜3件から外し、`今日のあとで`へ置く。同日中に自動で現在の一手へ戻さない | 条件をもう一度評価し、必要なら通常候補として出す。無条件繰越はしない |
| `今日は見送る` | その日の候補から外し、同日中は再提示しない | 条件をもう一度評価し、必要なら候補へ戻す |

`今日のあとで`から利用者が戻す場合、空き枠があれば戻せる。上限に達している場合は既存アクティブ1件との入替を選ぶ。

### 7.3 状態主役のカード例

| 状態事実 | 導出アクション | 今やる理由 | 終わりの条件 |
|---|---|---|---|
| 夜間セット そろそろ | 夜間セットを補充 | 寝る前にそろえておくと、夜中に探さずに済む | オムツ、ガーゼ、着替えが一か所にそろった |
| 夜間セット 最終確認: 昨日 | 夜間セットを確認 | 昨日の状態を今日の在庫とはみなさない | 今日の状態を3段階で確認した |
| 次サイズ 今日未確認 | オムツの次サイズを確認 | 月齢は確認のきっかけにだけ使う | 現在の様子を見て、買うか保留を決めた |
| 布団カバー 明日持ち帰り | 金曜の保育園セットを確認 | 持ち帰った後の置き場を先に決められる | 洗濯へ回す場所まで決めた |

保育園の例は、初回設定で保育園を有効にした場合だけ表示する。月齢情報は断定ではなく、確認するきっかけとして表現する。

## 8. 今日の0〜3件を選ぶ基準

候補は次の順で絞る。

| 優先 | 基準 | 例 |
|---:|---|---|
| 1 | 安全・期限 | 提出期限、通院準備など |
| 2 | 今日放置すると後工程が詰まる | 在庫補充、洗濯、夕食判断 |
| 3 | 状態が`そろそろ / 切れた` | 確認済み状態から必要な一手を出す |
| 4 | 余力に収まる | 5〜15分程度の一手へ分割 |
| 5 | 同種候補の重複回避 | 在庫確認だけで3件を埋めない |

今日のアクティブカード総数は常に余力上限以下、かつ絶対上限3件とする。表示されなかった候補は失敗や未完了にせず、利用者向けの集計対象にも入れない。

## 9. 先読み画面

予測AIではなく、設定とテンプレートから静的に最大3件を出す。

| 範囲 | 表示例 | 操作 |
|---|---|---|
| 明日 | 保育園の曜日差分、ゴミの日 | 今日準備へ入れる / そのまま |
| 今週 | 在庫確認、健診準備、提出期限 | 今日準備へ入れる / 後で見る |
| この先 | 次サイズ、離乳準備、安全対策 | 時期が来たら確認 / 今は不要 |
| 上の子設定が有効な家庭のみ | 上の子と2人だけの10分 | 今日準備へ入れる / 後で見る / 今は不要 |

先読み項目は自動的に今日へ入れない。`今日準備へ入れる`を押した時に今日枠が満杯なら、4件目を作らず、次の2択だけを出す。

1. 今日の既存1件を`今日のあとで`へ移して入れ替える
2. 今回は追加しない

無説明の失敗や、今日4件以上への増加は禁止する。

`上の子と2人だけの10分`は、関係改善の達成課題や子どもの感情の攻略として扱わない。補助コピーは`よくある波`までとし、感情の理由や結果を断定しない。

## 10. 担当画面

v0.2では担当領域を選択・認定する機能を実装しない。領域ごとの完結ループを読むだけにする。

| 領域 | 完結ループ例 |
|---|---|
| オムツ・消耗品 | 残量に気づく→必要量判断→注文→収納→次回確認 |
| 食事 | 方針決定→在庫確認→調達→準備→片付け |
| 保育園 | 連絡確認→差分判断→準備→提出→補充 |
| 洗濯 | 回収→洗う→乾かす→畳む→定位置へ戻す |
| 予定 | 情報収集→カレンダー反映→準備→当日対応→次回設定 |

担当状態、個別集計、工程別詳細、能力バッジはLaterとする。

## 11. 成長画面

件数、連続日数、夫婦比較ではなく、証拠イベントと`自分で気づけた`を中心に事実を見せる。

| 表示 | 内容 | 表示条件 |
|---|---|---|
| この家で起きなかった困りごと | `夜間セットを切らす前に補充できた`、`提出期限の前に準備を閉じた`など、明示的な前提記録と完了記録がつながる出来事 | テンプレートごとの固定証拠ルールを満たした場合だけ |
| 自分で気づけた | 提案前に必要事項を察知した記録 | 利用者が自分で記録した場合だけ |
| 次に気づくヒント | 次回に状態変化を見つけるためのサイン | 利用者が任意で残した場合だけ |

### 11.1 証拠イベントの境界

v0.2では`この2週間: 在庫切れ 0回`のような期間ゼロ集計を生成しない。記録がない時間を「起きなかった」とみなさない。

証拠カードを生成できるのは、コード上に固定ルールを持つテンプレートだけとする。

| 種別 | 最小証拠セット | 表示例 |
|---|---|---|
| 在庫・補充 | 同じ対象について当日の確認状態が`そろそろ`であること + その後に補充タスクを完了した記録 | `夜間セットを切らす前に補充できた` |
| 期限・予定 | 保存済みの期限・予定日時 + 期限前に準備完了した記録 | `提出期限の前に準備を閉じた` |

必要な証拠が1つでも欠ける場合は生成しない。`切れた`状態からの補充は「切らす前に」の証拠カードにしない。行動ログがない、状態が古い、期限が不明などの場合も推測しない。

証拠カードには誰の手柄かを示す主語を置かず、`よくやった`、`頑張った`などの称賛コピーも添えない。

### 11.2 「自分で気づけた」の入口

今日画面に、44px以上の副次ボタン`提案になかったことに気づいた`を常設する。

1. タップ時点で先読み達成を1件保存し、Undoを表示する。
2. 何に気づいたかのカテゴリ選択は任意とし、入力せず閉じられる。
3. XP、連続記録、順位、達成数の強調には使わない。
4. v0.2では自立度検証のローカル記録として使い、パートナーへ共有しない。

### 11.3 「1日1問」と卒業

1. 1日1回だけ、現在質問対象の領域から1問を表示する。通知で回答を迫らない。
2. `分かる`は状態把握の回答記録だけを残し、現在状態の鮮度は更新しない。
3. 同じ領域で`分かる`が2回連続したら、その領域を次の3日間だけ質問候補から外す。4日目から再び候補へ戻す。
4. `見てくる`または`十分 / そろそろ / 切れた`の状態記録が入った場合、上記クールダウンは解除して通常候補へ戻せる。
5. 質問頻度の調整はこの固定ルールだけとし、使用ペース推測や自由推論を行わない。
6. 未回答、`見てくる`、`切れた`を失敗・減点として扱わない。
7. 全ての質問対象領域がクールダウン中なら、その日は質問を出さない。

## 12. 状態と言葉

| 旧表現 | v0.2 | 意図 |
|---|---|---|
| 妻ケア | 休息をつくる | 相手をケア対象として扱わず、時間を作る行動へ |
| 妻の脳内カレンダーを奪う | 家族の予定を先に持つ | 敵対表現を自律的な行動へ変える |
| 取り逃がし | 次に気づくヒント | 相手の行動ではなく、自分が次に見つけられるサインを残す |
| 妻に聞かずに進める | 自分で決めて進める | パートナー回避ではなく自律を示す |
| 未回収 | 今日の候補外 | やらなかった失敗に見せない |
| 達成率 | 今日できたこと | 数値やゲージを使わず、完了した項目名だけを振り返る |

タスク状態は `今日やる / あとで / 今日は見送る / 完了 / もう済んでいた / 今は不要` を扱う。

`もう済んでいた`では、誰が対応したかを保存・表示・集計しない。任意で残せるのは次回に自分が早く気づくためのサインだけとし、パートナーの行動履歴は記録対象にしない。

禁止表現:

- `あなたのおかげで防げた`、`パパが守った`など主語つきの手柄
- `よくやってるね`、`頑張ったね`など根拠のない称賛
- `パパ嫌い解消`など子どもの感情を攻略対象にする言葉

## 13. 片手・疲労時のUX

- 主要タップ領域は44px相当以上。
- 本文は原則14px相当以上。
- 主要操作を色だけで区別しない。
- 完了は1タップ、直後にUndo可能。
- スワイプだけに依存しない。
- 夜間は無音、低刺激、強い白背景を避ける。
- アニメーションは短く、Reduce Motionへ対応できる構造にする。
- `今日は見送る`に理由入力を要求しない。
- localStorage保存に失敗した場合は利用者へ明示し、成功したように見せない。

## 14. v0.2の範囲

| Must | Later | Avoid |
|---|---|---|
| 2分以内の初回設定 | 通知方針の設定UI | パートナー承認 |
| 余力による0〜3件 | 残量ペースの自動学習 | 夫婦比較 |
| 理由・完了条件 | 自動卒業・自動間引き | 連続日数ペナルティ |
| 曜日・月齢の静的先読み | 家族アカウント同期 | 50件常時表示 |
| 大きなタップ操作とUndo | 担当領域の選択・認定 | 通知の常用 |
| 先読み達成の1タップ記録 | 担当領域の工程別詳細 | 完了率100%の強制 |
| 状態の3段階記録と鮮度管理 | 能力・担当領域ベースのゲーム成長表現 | 家事件数ベースのXP・レベル |
| 任意の「1日1問」 | 能力バッジ、個別集計 | 数値での残量入力 |
| 固定証拠ルールによる出来事記録 | AIによる自由推論 | 欠測からの`0回`推測 |
| `あとで`・見送り・入替の状態遷移 | 図鑑拡充 | 主語つきの手柄・空虚な称賛 |

## 15. 受入条件

| ID | 条件 |
|---|---|
| A-01 | 初回設定を2分以内で終え、今日の1件まで到達できる |
| A-02 | 今日画面のアクティブ状態カードは余力上限以下かつ0〜3件である |
| A-03 | 各状態カードに導出アクション、「今やる理由」、「終わりの条件」がある |
| A-04 | 余力を下げても、超過カードは失敗扱いせず`今日のあとで`へ移る |

## 16. v0.2の検証方法

最初は主要利用者本人による7〜14日間の実生活利用でC-01〜C-05を確認する。第三者への拡張性テストは、核を修正した後に行う。

| 検証対象 | 取得する最小情報 | 画面上の扱い |
|---|---|---|
| C-01 余力0〜3件 | 提示数、今やる選択、完了、あとで、見送り、入替 | 完了率や点数として見せない |
| C-02 理由カード | 理由カードを開いたか、先読み達成の1タップ | 自立度の順位や点数にしない |
| C-03 静的先読み | 今日へ入れた、後で見る、今は不要 | 不要提案の改善にだけ使う |
| C-04 状態主役のカード | 1日1問の回答、3段階状態、確認日、状態から選んだアクション | 未回答や`切れた`を失敗にしない |
| C-05 証拠イベント | 前提状態・期限、完了記録、表示後に役立ったか | 根拠のない項目は生成せずスコアにしない |

利用終了時に本人へ、負担、理由の納得感、先回りへの変化に加え、記録を見て育休を「取って損はなかった」と自分で言えるかを短く振り返ってもらう。パートナーは日常的な入力・承認・採点を行わない。希望がある場合のみ、一度だけ画面を見た印象を5分以内で聞き、監視・採点に見えないかを確認する。
