# v0.3 UX Slice — 実機フィードバック対応

Date: 2026-09-05
Status: Implemented on `ux/mobile-v03` / pending independent review and iPhone real-device verification

## 1. 背景

v0.2をiPhoneで実利用した直後、7〜14日テストを続ける前に次の問題が確認された。

- 下部ナビが本文へ重なり、スクロールが不安定になる
- `今やる`を経由するため、通常項目でも完了までのタップが多い
- `状態事実`、`今日の枠`など内部仕様寄りの文言が直感的でない
- カードが縦に長く、一覧性が低い
- 閲覧のみの`担当`タブを固定ナビへ置く価値が低い
- 朝に夜用・明日用の候補が上位へ出るなど、時間帯と優先順位が合わない
- 配色と視覚表現が「やさしい育児アプリ」に寄りすぎ、主要利用者本人の嗜好と合わなかった

この状態ではC-01〜C-05そのものよりUIの摩擦を測ることになるため、実生活テストを一度止め、P1相当の操作・レイアウト問題を先に直す。

## 2. v0.3の目的

プロダクト思想と保存形式を変えず、日常の割り込み下で「見て、その場で処理する」ためのモバイルUXへ刷新する。

## 3. 固定するUI

| 領域 | v0.3 |
|---|---|
| 配色 | 白〜暖色寄りの薄灰を基調に、アクセントはブルーグレー `#5F86A4` |
| イラスト | 使用しない |
| ナビ | `今日 / この先 / 記録` の3タブ |
| 設定 | 右上の歯車 |
| 今日の量 | `0 / 1 / 2 / 3件`を直接選択 |
| 今日一覧 | コンパクトなカード。カテゴリ、タイトル、短い補足、目安時間 |
| カテゴリ | `育児 / 家事 / その他` |
| 通常項目 | 一覧のチェックで1タップ完了。詳細からも完了可能 |
| 状態確認項目 | カード→ボトムシート→3段階状態→完了。状態選択済みなら最大2タップ |
| 詳細 | 下から出るボトムシート |
| 判断理由 | 詳細内の`判断のヒントを見る`へ格納 |
| 低頻度操作 | `…`に`あとで見る / 今日は出さない / もう済んでいる`を格納 |
| 完了取り消し | 完了チェック再タップまたはUndo |
| スクロール | 本文だけをスクロール。下ナビは別レイアウト行とし本文へ重ねない |
| 時間帯 | 朝・昼・夕方以降で候補の並び順を静的に調整 |

## 4. 変えないもの

- 保存キー `kajitori_stable_mvp_v2`
- `v02` namespace / version 2
- 旧rootの `tasksByDate / missedLog / retryQueue`
- 3段階状態の内部値 `enough / soon / out`
- 状態事実の鮮度ルール
- `そろそろ`相当の状態から補充完了した場合だけ在庫の先回り証拠を作るルール
- パートナー承認、夫婦比較、XP、連続日数を使わない方針

v0.3はデータ移行ではなくUX/UI刷新として扱う。

## 5. 今日の件数の意味

`今日の目標 0〜3件`は達成率や評価スコアではなく、その日にどれくらい持つかを示す利用者自身の負荷設定とする。

- `あと1件`などの追い込み表示はしない
- 達成率ゲージは出さない
- 未達を失敗扱いしない
- 候補一覧は判断材料として見せても、目標件数を達成義務へ変えない

## 6. 受入条件

### 操作

- [ ] 通常項目は一覧から1タップで完了できる
- [ ] 状態確認項目は未確認状態から最大2タップで状態記録＋完了できる
- [ ] 完了は取り消せる
- [ ] `あとで見る`は同日中に自動復帰しない
- [ ] `今日は出さない`は同日中に再表示しない

### モバイル

- [ ] iPhone Safariで下部ナビが本文を隠さない
- [ ] ホーム画面追加版でも本文だけがスクロールできる
- [ ] 主要タップ領域は44px相当以上
- [ ] ボトムシートが小画面でも操作可能

### データ

- [ ] 既存 `kajitori_stable_mvp_v2.v02` を読み込める
- [ ] v0.3起動だけで既存記録を削除しない
- [ ] localStorage書込失敗時に操作をロールバックする
- [ ] 旧rootデータを保持する

### 配信

- [ ] service workerのcache名を更新し、旧UI資産を残さない
- [ ] Pages artifactへv0.3 CSS/JSを含める
- [ ] `index.html` / manifest / appのtheme colorをブルーグレーで統一する

## 8. 公開前の停止条件

以下のいずれかが残る場合はPages本番公開を止める。

- JavaScript構文エラー
- 既存保存データを壊す変更
- 下部ナビの重なり再発
- 完了・Undo・状態記録の中心フローが実機で動かない
- P0/P1 findingが未解決

ローカル環境ではブラウザ起動が組織ポリシーで制限されるため、最終的なSafari実機確認は公開候補のiPhone確認で行う。
