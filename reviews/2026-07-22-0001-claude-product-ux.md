# Product & UX review (2026-07-22)

## 1. プロダクトの一文と最初の利用者

「家庭の次の一手に自分で気づき、判断し、閉じる力を育てる先読みトレーナー」。最初の利用者は、新生児と上の子(保育園児)を持ち、日中は仕事で不在、朝晩と週末が主戦場の父親。

## 2. 「分かってる」と感じる5場面

| 場面 | 隠れた負担 | アプリの気遣い | 喜ばれる理由 |
|---|---|---|---|
| 夜間授乳明けの朝 | 睡眠3時間でも通常量のタスクが並ぶ絶望 | 起床時に余力を1タップ申告→今日の提案を3件まで自動圧縮 | 「今日はこれだけでいい」と判断ごと軽くしてくれる |
| 保育園の朝支度 | 曜日ごとの持ち物差分(布団・着替え補充)の記憶 | 前夜に「明日は金曜、布団カバー」を先出しし、朝は確認だけ | 朝の思考ゼロ。玄関で気づく事故が消える |
| 消耗品の残量 | おむつ・ミルクの「そろそろ?」に気づくのは常に相手 | 補充記録から消費ペースを学習し「あと4日」を残量前に提示 | 聞かれる前に買ってある、が初めて実現する |
| 夕方の魔の時間 | 黄昏泣き×上の子の夕食×風呂の段取り崩壊 | 17時台を1本の段取りに束ね「今は米を炊くだけ」と現在の一手のみ表示 | 全体を考えず手だけ動かせる。破綻しても再計算 |
| 寝かしつけ後 | 明日の準備を考える気力が残っていない | 片手60秒で「明日の先読み3件」を確認して終了 | 寝る前の不安が消え、翌朝の自分に引き継げる |

## 3. 象徴的機能トップ5

| 機能 | 解決する負担 | Wowポイント | 注意点 |
|---|---|---|---|
| 余力ダイヤル | 体調無視の固定ノルマ | 未完了は繰越でなく「今日は守る日と判断した」として閉じる | 低余力の常態化を責めない文言に |
| 理由カード | なぜ今それかが分からず指示待ち化 | 各提案に根拠(月齢・曜日・間隔)を明示し、判断基準ごと学べる | 根拠は1行。説教にしない |
| 卒業設計 | アプリ依存の固定化 | 提案前に自分で気づいた項目は「先読み達成」となり、以後その提案が減る | 利用時間減=成功をKPIに握る覚悟が要る |
| 抱っこ片手モード | 両手が塞がる時間が長い | 親指圏の大ボタン+スワイプ完了、5秒で操作終了 | 夜間は無音・減光を既定に |
| 気づきログ | 相手が先にやった事実が敗北になる | 「どのサインで気づけたか」を1タップ記録し翌日の先読みに変換 | 競争・スコア化の見た目を排除 |

## 4. 画面構成と利用フロー

4タブ: **今日**(余力+3件+現在の一手) / **先読み**(明日以降の芽、在庫、予定) / **気づき**(気づきログと学び) / **成長**(図鑑・卒業状況)。

- 朝30秒: 余力申告→今日の3件を確認、持ち物差分だけ読む。
- 日中: 通知は原則なし。ちら見で「現在の一手」のみ。完了はスワイプ。
- 夜60秒: 寝かしつけ後に明日の先読み3件と気づき1件を閉じて終了。

## 5. マイクロコピー改善

| 現在 | 改善案 | 理由 |
|---|---|---|
| 妻ケア | パートナーの回復 | 性別固定を外し、ケア対象扱いでなく回復という目的語に |
| 妻の脳内カレンダーを奪う | 家族の予定を先に持つ | 「奪う」は敵対的。持つ主体の交代を肯定形で |
| 取り逃がし | 先に済んでいた | 獲物を逃した competitiveな響きを事実の記述に |
| 妻に聞かずに進める | 自分で決めて進める | 回避でなく自律が目的だと示す |
| 達成率0% | 今日は守る日 | 数字の欠損を責めず、その日の判断として承認 |

## 6. MVP優先順位

- **Must**: 初回設定(家族構成・月齢・保育園)、今日3件+理由カード、余力ダイヤル、片手完了、曜日/月齢ベースの静的先読み。
- **Later**: 残量ペース学習、卒業設計の自動間引き、気づきログの先読み変換、図鑑拡充。
- **Avoid**: パートナーの入力・承認・採点、夫婦間の達成比較、通知の常用、50件一覧の常時表示、連続記録が途切れるペナルティ。

## 7. 実装前の質問

1. パートナーはアプリの存在を知っている前提か、利用者単独の完全非同期か。気づきログの記録粒度と文言が変わる。
2. 主要利用者は復職済み(朝晩型)か育休中(終日型)か。時間帯設計と「今日3件」の中身が変わる。
3. 成功指標は何か。卒業設計は利用減=成功であり、継続率KPIと矛盾する。どちらを取るかで成長設計の深さが決まる。

## 8. Codex response

| Claude提案 | Status | 応答 |
|---|---|---|
| 「先読みトレーナー」という定義 | Accepted | タスク管理との差が一文で伝わり、P-01・P-02・P-09を統合できる |
| 最初の利用者を日中不在・朝晩型の父親とする | Rejected | 出発点は育休中に家庭運営を担う終日型。復職後は拡張フェーズとして扱う |
| 5つの生活場面 | Accepted | 生活場面から機能を考える方向は妥当。ただし夜の確認を新たな義務にしない |
| 余力ダイヤル | Accepted | 低余力を正当な判断として扱える。入力は任意の1操作以内に限定する |
| 理由カード | Accepted | 指示だけでなく判断基準を学ばせる中核機能にできる |
| 卒業という成功思想 | Accepted | 継続利用より自立を優先する思想は本プロダクトに合う |
| 自動で提案を間引く卒業機構 | Deferred | 誤学習や必要タスクの消失を避けるため、v0.2では卒業状況の可視化までとする |
| 抱っこ片手モード | Accepted | 必須UX。スワイプだけにせず、大きなタップ操作とUndoも用意する |
| 今日・先読み・気づき・成長の4タブ | Deferred | 根幹となる「担当領域」が消えている。気づきを成長内へ統合し、担当領域を主要導線へ戻す案を比較する |
| マイクロコピーの改善方向 | Accepted | 敵対・競争表現を外す方向は妥当。最終語は利用者テスト前に確定しない |
| `Must / Later / Avoid` の仕分け | Accepted | v0.2の仕様作成時の初期優先順位として採用する |
| 卒業と継続率のどちらを成功とするか | Deferred | プロダクト判断が必要。Codexは自立度を優先し、必要な節目に戻る利用を推奨する |
