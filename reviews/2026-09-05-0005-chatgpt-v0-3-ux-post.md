## Findings

### [P1][Resolved] 「この先」から明示追加した項目が今日一覧に見えない場合がある

| 項目 | 内容 |
|---|---|
| Location | `kajitori_v03_actions.js` / Today候補の並び順 |
| Observation | `next_size`等を「今日の一覧に追加」しても、上位5件の静的優先度に押し出されると一覧に表示されないケースがあった |
| Impact | 利用者が明示的に追加した操作結果が画面へ反映されず、中心操作の信頼性を損なう |
| Principle | P-02 / D-027 |
| Recommendation | 明示追加した項目をToday並び順で優先する |
| Evidence | Smoke testで再現。`currentId`へ追加項目を保持し`timeScore`で最優先にした後、再検証 |

Implementer response: **Accepted / Fixed**

### [P1][Resolved] オムツ証拠イベントが実際より強い完了事実を主張する

| 項目 | 内容 |
|---|---|
| Location | `kajitori_v03_core.js` / `diaper_stock.evidenceText` |
| Observation | 終了条件は「必要なら購入メモを作る」なのに、旧文言は「切らす前に補充できた」と表示していた |
| Impact | 実際に補充した証拠がないのに補充完了を主張し、D-017/D-020の証拠境界を破る |
| Principle | P-01 / D-017 / D-020 |
| Recommendation | 観測できた事実だけへ文言を弱める |
| Evidence | `オムツが少ない段階で気づけた`へ変更し、テストで完全一致を確認 |

Implementer response: **Accepted / Fixed**

### [P1][Resolved] 完了を戻した後も証拠イベントが残る

| 項目 | 内容 |
|---|---|
| Location | `kajitori_v03_core.js` / `reopenTask` |
| Observation | 完了操作で生成した証拠をチェック再タップで取り消しても、同日のevidence eventが残る状態だった |
| Impact | 現在の記録と証拠表示が矛盾する |
| Principle | D-017 / D-020 |
| Recommendation | 完了を戻す時、同日・同templateの派生証拠も取り消す |
| Evidence | `reopenTask`で対象eventを削除。スモークテストで削除→再完了→再生成を確認 |

Implementer response: **Accepted / Fixed**

### [P2][Resolved] `今日は出さない`項目が「この先」から同日に再提示される

| 項目 | 内容 |
|---|---|
| Location | `kajitori_v03_actions.js` / `renderForecast`, `addForecast` |
| Observation | Todayでdismissedにした項目がForecast候補生成側では除外されず、同日中に再追加できた |
| Impact | 「今日は出さない」の意味が崩れる |

| Evidence | render/add両方へ防御を追加 |

Implementer response: **Accepted / Fixed**

### [P2][Resolved] 完了済み詳細から低頻度操作を選べる
