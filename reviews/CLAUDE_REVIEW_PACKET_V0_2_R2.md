# Claude review packet: v0.2 two-layer concept revision R2

Status: Active
Date: 2026-07-23

## 役割

育児家庭の生活解像度が高いシニアプロダクト企画者兼UXデザイナーとして、承認済みの二層コンセプトがv0.2仕様へ矛盾なく反映されたかを事後レビューする。今回は新しいコンセプト提案やUI制作ではなく、文書改訂の欠陥と実装前リスクを絞り込む。

## 読む範囲

1. このパケット
2. `docs/V0_2_UX_SPEC.md` 全文
3. `docs/PRODUCT_BRIEF.md` の§1〜§3、§6
4. `docs/DECISIONS.md` のD-016〜D-019だけ

上記だけで判断する。HTML、JavaScript、`prototypes/`、旧レビュー、`HANDOFF.md`、外部情報は読まない。

## 確定事項

| ID | 変更しない前提 |
|---|---|
| D-009 / D-012 | 最初の利用者は育休中に家庭運営を担う父親。新生児家庭が基本で、上の子・保育園は任意設定 |
| D-013 / D-014 | 数値ゲージを使わず、主要利用者本人が7〜14日間検証する |
| D-016 | カードは家の状態事実を主役にし、アクションは従に置く |
| D-017 | 起きなかったことは、記録に基づき、主語なし・称賛なしで示す |
| D-018 | 任意の「1日1問」を状態把握と卒業の中核にし、未回答を罰しない |
| D-019 | 名称変更はProposedのまま。今回のレビューで名称を決定しない |

確定事項の賛否を再議論せず、それらが仕様として安全かつ検証可能に定義されているかを確認する。

## 優先して見る観点

| 優先 | 観点 | 確認したいこと |
|---:|---|---|
| 1 | 状態主役 | 視覚・情報の最上位が確認済みの状態事実で、タスク指示が再び主役になっていないか |
| 2 | 証拠の境界 | `起きなかったこと`を、欠測や行動ログだけから推測する余地がなく、表示可否を実装できるか |
| 3 | 尊厳 | 主語つきの手柄、空虚な称賛、パートナーの監視・採点に見える挙動が残っていないか |
| 4 | 1日1問 | 1〜2タップで任意に終えられ、未回答を罰せず、残量自動学習なしで質問を減らせるか |
| 5 | MVP範囲 | Must追加に対する相殺が十分で、C-01〜C-05を7〜14日で検証できるか |
| 6 | 上の子 | `上の子と2人だけの10分`が子どもの感情の攻略や結果保証になっていないか |

特に、次の境界事例を確認する。

- 状態記録が数日欠けたのに`在庫切れ 0回`と表示される。
- `分かる`を続けた領域の質問が減り、後から状態が変わる。
- 守る日0件で、表示根拠のある記録が1件もない。
- パートナーが偶然、成長画面と上の子向け項目を見る。

- 医療・安全情報の正確性調査
- 同期、バックエンド、課金、通知基盤
- D-009、D-012〜D-018の再決定、D-019の名称案出し
- 合意範囲を越える新機能の提案

## 出力契約

`reviews/2026-07-23-0003-claude-v0-2-r2.md`だけを新規作成する。全体を日本語2,800字以内とし、次の順で表を中心に書く。

1. 総合判定: `Ready / Revise`、理由を2文以内
2. Findings: 最大5件。`Severity / 仕様箇所 / 境界場面 / 確認できた問題 / 影響 / 最小改善`。P0〜P2のみ
3. 受入条件確認: A-11〜A-14を各`Pass / Gap`で判定し、根拠箇所を1行ずつ示す
4. MVP相殺確認: `十分 / 不十分`と、MustからLaterへ移す必要があるものだけ最大2件
5. 実装前に回答必須の質問だけ最大3件。なければ`なし`

同意や仕様要約を長く再掲しない。文言の好みだけの指摘、根拠のない機能追加、実装コードは書かない。指定した結果ファイル以外は変更せず、作成したら終了する。
